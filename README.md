# Routeliner для RustGIS

Routeliner для RustGIS ставит события на маршруты и ведёт пикетаж в
RustGIS так же, как модуль QGIS Routeliner. Номера инструментов, имена
полей `rl_*` и коды ошибок у расширения и у модуля одни и те же. Мы
переносим расчёт модуля на Rust по шагам и сверяем каждый инструмент
с прогонами модуля.

Английская версия этого текста с теми же разделами и таблицами лежит
в [README.en.md](README.en.md).

## Инструменты

| Код | Инструмент | В расширении |
|---|---|---|
| 1.01 | Демонстрационный пример | нет, причина в разделе об ограничениях |
| 1.02 | Проверка маршрутов | есть |
| 1.03 | Калибровка маршрутов | есть |
| 2.01 | Точечные события | есть |
| 2.02 | Участки (линейные события) | есть |
| 3.01 | Динамический слой точечных событий | нет, тот же расчёт даёт 2.01 |
| 3.02 | Динамический слой участков | нет, тот же расчёт даёт 2.02 |
| 4.01 | Пикетная разбивка | есть |
| 4.02 | Привязка точек к маршрутам | есть |
| 5.01 | Таблица профиля | следующий шаг |
| 5.02 | Чертёж профиля | следующий шаг |

Инструмент 1.02 собирает маршрут из всех объектов с одним ID, упорядочивает
части по стыкам и отдаёт маршруты с разрывом или развилкой в таблицу
ошибок. Инструмент 1.03 берёт пикетаж из контрольных точек, ведомости
с пикетажными уравнениями или длины по оси и пишет пикетаж начала и конца
каждого маршрута.

Инструменты 2.01 и 2.02 ставят записи таблицы на маршруты по пикету или
по паре пикетов, со смещением от оси. Инструмент 4.01 ставит точки целых
пикетов с учётом вставок, а 4.02 находит для точки ближайший маршрут,
меру, пикет и смещение. Итог событий и привязки повторяет поля исходной
записи и добавляет поля `rl_*`. Запись, которую нельзя поставить, попадает
в таблицу ошибок вместе со своими полями.

## Сверка с модулем

Сверка идёт по файлу `fixtures/tool_runs.json` модуля Routeliner 0.5.2. Его
собирает сценарий `tools/make_tool_runs.py` модуля на примере 1.01 с зерном
1 в зоне UTM 40N на WGS 84, расчёт ведёт ядро модуля без QGIS. Копия файла
без правки лежит в папке `fixtures` этого репозитория, а пересобирает его
только модуль.

| Инструмент | Прогоны модуля |
|---|---|
| 1.02 | по умолчанию, с разрывами, в обратном направлении |
| 1.03 | ведомость с пикетажем в M, ведомость с мерой в M, контрольные точки |
| 2.01 | ведомость, пикетаж в M, смещение вправо |
| 2.02 | ведомость, пикетаж в M, мера в M |
| 4.01 | шаг 100 м с ведомостью, шаг 500 м с пикетажем в M, шаг 100 м по длине |
| 4.02 | радиус 50 м, радиус 5 м |

На всех 17 прогонах поля совпадают без отклонений, вершины расходятся не
больше чем на 6·10⁻¹¹ м, M не больше чем на 5·10⁻¹¹ м. Эти значения печатает
тест `tests/tool_runs.rs` при запуске `cargo test -- --nocapture`. Допуск прогона равен 10⁻⁹ для полей и 10⁻⁶ м
для вершин и M, а предел задания равен 0,001 м. Пояснения `rl_message`
тест сравнивает по-русски слово в слово.

Python округляет `round(x, 3)` по точному двоичному значению, а ровную
половину отдаёт чётной цифре. Расширение округляет поля `rl_*` и подписи ПК тем
же правилом, поэтому подпись вида «ПК 14+71.24» совпадает с модулем знак
в знак.

Тест `tests/rustgis.rs` проверяет путь через RustGIS целиком для 1.02,
1.03, 2.01 и 4.02. Слои примера идут в градусах WGS 84 без Z, как их
отдаёт RustGIS. Длины, меры, координаты и смещения сходятся с прогоном
модуля в пределах 0,001 м.

## Ограничения RustGIS 0.6.0

RustGIS отдаёт слои в градусах WGS 84 без Z и без M. Крейт `rustgis-kit`
переводит их в метры зоны UTM по середине входа, а итог возвращает
в градусах. Из этого перевода и из устройства RustGIS следуют пять
различий расширения с модулем.

- Пикетаж из M-значений геометрии не работает, потому что у слоя RustGIS
  нет M. Поля «Пикетаж из M-значений геометрии» и «Метров в единице M»
  в окне RustGIS скрыты, и маршрут без ведомости получает пикетаж по длине.
- M-значения итога 1.03, 2.01, 2.02 и 4.01 расширение считает, а в слой
  RustGIS они не попадают. Пикетаж и мера остаются в полях итога.
- Инструмента 1.01 нет, потому что он пишет папку с GeoPackage и растром,
  а у крейта нет поля папки и выхода набором слоёв.
- Динамических слоёв 3.01 и 3.02 нет, потому что пересчёт слоя при правке
  маршрутов и таблиц требует сессий расширений, а они ещё не вышли
  в выпуске RustGIS. Тот же расчёт одним запуском дают 2.01 и 2.02.
- Дуг в GeoJSON нет, маршрут приходит уже отрезками, и расширение считает
  длину по этим отрезкам. Модуль режет дугу сам, через 0,02° на хорду
  (`CURVE_ANGLE_DEG` в `layers/route_source.py`).

## Сборка и проверка

Крейт `rustgis-kit` подключён зависимостью git с
[github.com/Valery35/rustgis-kit](https://github.com/Valery35/rustgis-kit)
по тегу v0.1.7.

```bash
cargo build
cargo test
cargo clippy --all-targets -- -D warnings
```

Раздел `tools` файла `plugin.json` строится из описаний инструментов.
Тест `plugin_json_is_current` сверяет файл с описаниями, а переменная
окружения `ROUTELINER_WRITE_MANIFEST=1` при запуске `cargo test`
переписывает его.

Пакет собирает сценарий `scripts\package.ps1`. Он делает сборку release
и вызывает сценарий упаковки крейта из соседней папки `..\rustgis-kit`.
В папке `dist` появляются папка `routeliner` для «Add Plugin Folder…»
и пакет `routeliner-0.1.0.rgplugin` для установки из файла.

```bash
powershell -File scripts/package.ps1
```

Описания `fixtures/tools.json` и прогоны `fixtures/tool_runs.json` берутся
из папки `fixtures` модуля без правки. После пересборки прогонов в модуле
обе копии заменяются целиком.

## Устройство

| Папка или файл | Содержание |
|---|---|
| src/core | Ядро, перенос `routeliner/core` модуля. Пикеты, система пикетажа с уравнениями, геометрия маршрута с M, сборка маршрута, постановка событий, коды ошибок |
| src/tools | Инструменты по значениям прогона модуля, чтение маршрутов, ведомости, событий и точек |
| scripts | Сборка пакета `.rgplugin` |
| src/product.rs | Продукт крейта `rustgis-kit`, команда «О расширении», основа `plugin.json` |
| src/pyfmt.rs | Округление и шаблоны сообщений так, как их пишет Python модуля |
| fixtures | Описания инструментов и прогоны модуля, копия без правки |
| tests | Сверка с прогонами и путь через RustGIS |
